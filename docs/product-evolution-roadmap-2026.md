# 知远智能体产品演进与重构路线图 (2026-10)

> **目标**：从「拼凑式功能工具箱」向「以工作为中心、有温度的 AI Native 协作执行平台」演进。  
> **关键保留**：保留本地推理与模型管理（结合公司桌面 GPU 硬件，作为核心算力底座）。

---

## 核心设计理念转变

| 维度 | 现状（散装工具箱） | 目标（以「工作」为中心的同事） |
| :--- | :--- | :--- |
| **组织中心** | 功能页面（Chat、Cowork、Coding、Todo、Cron、Expert 各自为政） | **统一对象：工作 (Work / Project)** |
| **首屏体验** | 冰冷的居中空白 Prompt 输入框，等用户想问题交代背景 | **工作简报 (Briefing)**：等你决策、已自动推进、建议下一步 |
| **执行模式** | 多套互相割裂的会话体系 | 同一工作下，由 Agent 协作执行，并可利用本地 GPU 高效跑批 |
| **交互温度** | 工具日志与流水账刷屏，机械式状态 | **先结论后过程**，过程默认折叠，文案人性化平实表达 |
| **算力角色** | 本地推理仅作为一个游离在外的功能页 | **核心底座优势**：突出「本地 GPU 加速、隐私保护、不耗 Token」的硬件伴侣体验 |

---

## 四个演进阶段 (Phases)

### Phase 1：侧栏瘦身与导航结构归拢（立即执行）

- **核心目标**：迅速去除“东拼西凑”的第一视觉印象，将侧边栏视口收缩聚集在核心主线。
- **具体动作**：
  1. **侧栏一级入口精简**：
     - 主导航保留：**会话与工作 (Work / Chat)**、**本地推理 (Local Inference / GPU)**。
     - 底部常驻：**技能与能力 (Skills & MCP)**、**设置 (Settings)**。
  2. **收起游离与孤立模块**：
     - 隐藏 `expert`（专家）等孤立入口，不再常驻占用侧栏一级视口。
     - 将 `todo`、`scheduledTasks`、`activity`、`coding` 从侧栏主导航剥离或收起，为后续收归为“工作子项”打底。
  3. **视觉与交互对齐**：
     - 保持 32px 导航行规格，符合 [DESIGN.md](DESIGN.md) 规范。
     - 修正 reselect 与测试断言，确保全流程无编译和回归告警。

---

### Phase 2：首页改造（工作简报替代纯空白输入框）

- **核心目标**：解决“打开软件不知道干什么”、“用户不提问系统就装死”的冷冰冰体验。
- **具体动作**：
  1. **建立「今日工作简报 (Briefing)」投影**：
     - 聚合底层现有的 SQLite 运行记录与定时任务交付物。
     - 首页三栏清晰展示：
       - **等你决策**：需要审批的权限、需要确认的外发与代码分支操作。
       - **已为你推进**：夜间/后台 Cron 任务产出、本地 GPU 批处理已完成事项。
       - **建议下一步**：根据上下文推断的可一键继续推进的任务。
  2. **输入岛降级为常驻辅助工具**：
     - 保留底部快捷输入能力，但不再充当唯一的空洞视觉中心。

---

### Phase 3：对话与结果呈现重构（温度与品质落地）

- **核心目标**：消除工具过程刷屏与高认知负荷，实现高品质、有温度的交互。
- **具体动作**：
  1. **消息气泡「结论优先」**：
     - 统一使用 `ai-elements` 封装。
     - 交付物、代码变更摘要置顶，数十步的 bash/文件操作折叠至「▸ 执行详情」。
  2. **决策卡重构**：
     - 权限审批与操作确认由机械的弹窗改为清晰明确的决策卡：
       - 说明“要做什么”、“为什么做”、“有何影响”、“提供哪几种选项”。
  3. **去技术黑话文案**：
     - 去除对用户暴露的引擎内部名词（如 turn、runtime、harness、agentEngine），改用自然贴切的同事口吻。

---

### Phase 4：本地推理（GPU 硬件）与执行体验闭环

- **核心目标**：将公司的硬件算力优势转化为产品的护城河，让软硬件协同发力。
- **具体动作**：
  1. **深度打磨本地模型体验**：
     - 保留并优化 `llamacppManager`，增加显存与 GPU 算力占用可视化。
     - 提供工作维度的「优先本地运行 (GPU)」模式，保证数据不出机。
  2. **弹性运行时与持久化保障**：
     - 结合 Pi 运行时，打磨任务中断重试与检查点续跑机制，减少因应用关闭导致的挫败感。
  3. **软硬一体化包装**：
     - 完善桌面硬件检测机制，针对不同 GPU 规格自适应推荐最适合的本地模型与上下文配比。

## 技术栈整体建议与取舍

围绕「服务黄金路径、杜绝拼凑感、减轻维护负担」，对现有及演进中的技术栈进行分类定调：

| 模块 / 技术 | 建议 | 详细理由与实施方案 |
| :--- | :--- | :--- |
| **Electron + React + Vite + Tailwind** | **坚定保留** | 桌面端最佳实践，生态成熟稳定，当前问题不在框架本身。 |
| **Base UI (shadcn) + ai-elements** | **坚定保留并强制标准** | 统一所有控件和消息流呈现，杜绝重复自造样式与组件。 |
| **本地推理引擎 (llama.cpp / llamacppManager)** | **保留并作为核心资产打磨** | 公司桌面 GPU 硬件的直接依托。保留 `libs/llamacppManager.ts` 和 `src/shared/llamacpp/`，强化显存与推理监控，作为任务执行的第一梯队选择。 |
| **Pi Runtime 内核架构** | **阶段性演进 / 拥抱持久化原生** | 当前 `piRuntimeAdapter.ts`（4500+ 行）自建了大量持久化、排队、子 Agent 与中断机制，是复杂度主要来源。<br/>• **短期**：在现有 adapter 上收敛业务协议，不增加新 gate；<br/>• **中长期**：向 `Pi Durable` 原生 Task/Document/Checkpoint 架构对齐，减少在 harness 层的定制缝补。 |
| **SQLite 存储 (better-sqlite3)** | **保留** | 保证桌面端本地数据的可靠读写。后续随着 Work 模型的建立，逐步将分散表合并收敛。 |
| **记忆系统 (Engram)** | **简化与收敛** | 避免复杂的跨域多层记忆纠缠。优先做实每项工作的「工作档案 (Dossier)」，用户可见、可纠偏，减少强制人工确认的摩擦。 |
| **主题系统 (Theme Engine)** | **大幅度减负** | 不再维护多套复杂主题与主题生成引擎的无限排列组合。固定为**一套克制的高品质设计（浅色 / 深色 / 跟随系统）**，减少 50% 以上无意义的 UI 维护成本。 |
| **外围游离模块 (Coding / Expert / IM 渠道)** | **收编或冻结** | • `Coding Agent`：不再作为独立客户端模式，收归为 Work 下的代码执行能力；<br/>• `Expert` / `Companion`：冻结入口，不再占用侧栏视口；<br/>• `cc-connect`（IM 渠道）：重心先放在本地桌面闭环，不分散精力在外部平台对接。 |
